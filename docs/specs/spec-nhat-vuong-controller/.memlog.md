- (event) 23 capability IDs assigned; IDs are now stable and must never be reused or renumbered.
- (constraint) Control rights originate from the timetable, never from an end user scanning a QR code; QR is administrator device registration only (SRS note 6.5-3).
- (constraint) Lecturer command overrides class monitor on conflict, monitor notified (FR-A5). Promoted from US-07 to a kernel constraint because it is an arbitration rule affecting the whole authorisation design.
- (constraint) Every command authorised server-side, client never trusted (NFR-05). Kept in the kernel as well as quality-constraints.md because it rules out client-side rights checks architecturally.
- (constraint) Device state read from the control board, never inferred from the last command sent (FR-C1).
- (constraint) Margin, X, N, minimum setpoint and operating hours are administrator-configurable at deployment, never hard-coded (SRS note 6.5-2).
- (constraint) A rejected command leaves device state unchanged and is still audit-logged (FR-B4 exception path plus FR-F5).
- (decision) Non-goals set: no end-user QR claiming; no device classes beyond air conditioners; no external BMS/BACnet integration; no learned setpoints; no billing or chargeback from runtime data.
- (assumption) Non-goals for BMS integration, other device classes, learned setpoints and billing are inferred from absence of any covering requirement, not from explicit exclusion in the source.
- (assumption) Timetable is authoritative and current; CAP-2 rights are only as correct as the CAP-16 import.
- (assumption) Device module can read the control board of whatever air conditioners the university already owns; source names no brand, model or protocol.
- (question) Which air-conditioner brands and control-board protocols must the device module support? Decides one hardware design versus per-brand variants.
- (question) CAP-10 switches off every running unit at the closing hour, but CAP-2 grants rights for class plus margin. What happens to a class still running at closing time? Unresolved contradiction in the source.
- (question) How does a class monitor obtain control rights at all? The precedence constraint implies they hold them but no requirement grants them.
- (question) What is the timetable file schema, and how do its columns resolve to registered devices?
- (question) If the device module fails or is removed, does the air conditioner remain operable from its physical remote? Source silent on fail-safe behaviour.
- (question) SRS sections 1-5 are cited throughout the source but absent from this repository; they may carry scope or architecture decisions this contract should inherit.
